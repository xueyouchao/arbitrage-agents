Failure Paths
⚡ fetch → failedScanResult(category: 'fetch') → save failed scan
⚡ processing → failedScanResult(category: 'processing') → save failed scan
⚡ persistence → failedScanResult(category: 'persistence') → save failed scan
⚡ step failure → failWithCheckIn() → record step 'failed' + Sentry error()
All failures are isolated: LLM gateway errors are caught and treated as "no review available".
Paper-trade simulator errors are caught per-opportunity. Sentry check-in failures are always swallowed.
The saveFailedScanRun() helper itself is wrapped in try/catch — the original failure is always returned.
